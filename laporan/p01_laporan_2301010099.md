## 1. Tujuan Praktikum
Mampu menjalankan dan menghentikan layanan MariaDB lewat XAMPP Control Panel, terhubung melalui CLI dan phpMyAdmin, mengamankan akun root, membuat akun kerja berhak akses minimum, serta mengelola repositori tugas dengan Git dan GitHub.

---

## 2. Ringkasan Dasar Teori
DBMS berfungsi mengelola penyimpanan, integritas, dan keamanan basis data melalui arsitektur klien-server, di mana klien (CLI atau phpMyAdmin) mengirim perintah SQL ke proses server `mysqld` di port 3306. Pengamanan sistem diterapkan melalui prinsip hak akses minimum (*least privilege*), penggunaan akun kerja khusus, serta pengamanan phpMyAdmin dengan mode *cookie*. Seluruh pengerjaan praktikum dilacak menggunakan sistem kendali versi Git secara bertahap.

---

## 3. Hasil Langkah Percobaan
* Layanan MariaDB berhasil dijalankan pada port 3306 melalui XAMPP Control Panel.
* Berhasil masuk melalui CLI dengan akun `root`, melakukan pengecekan versi (`10.4.32-MariaDB`), dan memeriksa mode SQL server (`STRICT_TRANS_TABLES`).
* Akun `root` telah diamankan dengan password.
* Basis data `kopma_099` dan akun kerja `mhs_099` berhasil dibuat dengan hak akses terbatas hanya pada `kopma_099.*`.
* Pengaturan phpMyAdmin diubah ke mode `cookie` pada berkas `config.inc.php` sehingga mewajibkan autentikasi login.

---

## 4. Jawaban Titik Analisis
* **Titik Analisis 1:** Karena XAMPP memakai MariaDB (meski label tombol bertuliskan MySQL), dokumentasi MySQL masih relevan untuk sintaks dasar SQL. Namun untuk fitur khusus, variabel server, atau kode galat spesifik, rujukan utama harus menggunakan dokumentasi resmi MariaDB.
* **Titik Analisis 2:** Pesan galat `Access denied for user 'root'@'localhost' (using password: NO)` menunjukkan bagian `(using password: NO)` yang memberi tahu bahwa klien mencoba masuk tanpa mengirimkan parameter password (`-p`).
* **Titik Analisis 3:** Akun `mhs_099` dapat melihat `information_schema` karena berisi metadata sistem yang diizinkan untuk semua pengguna, sedangkan akses ke basis data `mysql` ditolak (`ERROR 1044`) karena `mhs_099` tidak diberi hak akses atas basis data sistem tersebut. `ERROR 1044` berarti akses ditolak ke basis data tertentu (*database access denied*), sedangkan `ERROR 1045` berarti gagal autentikasi saat masuk/login (*login access denied / bad credentials*).
* **Titik Analisis 4:** Mode `cookie` lebih aman karena password tidak disimpan secara terbuka (*plain text*) di dalam berkas konfigurasi server, melainkan meminta sesi autentikasi pengguna secara aktif setiap kali masuk ke peramban.

## 5. Hasil Latihan dan Modifikasi
* Membuat akun `tamu_099` yang hanya memiliki hak `SELECT` pada `kopma_099`. Saat mencoba `CREATE TABLE uji (id INT);`, server menolak dengan `ERROR 1142 (42000): CREATE command denied to user 'tamu_099'@'localhost'` yang menegaskan bahwa akun hanya memiliki hak baca.
* Skrip `p01_lingkungan_2301010099.sql` diperbarui dengan klausa `CREATE DATABASE IF NOT EXISTS` dan `CREATE USER IF NOT EXISTS` agar dapat dijalankan berulang kali (*idempotent*) tanpa menghasilkan galat.

## 7. Pembahasan dan Kendala
* **Kendala:** Mengalami masalah kerusakan tabel sistem (`ERROR 144 / ERROR 1034: Table '.\mysql\db' is marked as crashed`).
* **Solusi:** Melakukan perbaikan tabel sistem dengan mereset folder data MySQL menggunakan cadangan bersih bawaan dari `C:\xampp\mysql\backup`, sehingga layanan MariaDB kembali normal dan pembuatan user berhasil dilakukan.
